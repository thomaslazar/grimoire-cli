# Generated API client — design

**Date:** 2026-08-11
**Status:** Design approved, not yet implemented.
**Targets:** Grimoire **v1.5.5**.
**Supersedes:** the hand-written request surface in `ApiEndpoints.cs` and
`QueryBuilder.cs`.

---

## 1. Why this exists

The CLI's request surface is currently transcribed by hand from upstream source.
That has worked, but only because every claim was verified by reading
`temp/grimoire/` — and it has silently drifted before. Grimoire publishes an
OpenAPI spec; a published contract is a better source than a careful reading,
and generating from it is what makes the surface reliable rather than
well-intentioned.

Two concrete wins, both measured rather than assumed:

- **Query parameters come from the contract.** `GET /api/systems` declares 12.
  We hand-derived `parent_id` and `include_children` from `core.py` during the
  1.5.5 work; the generator produces all 12 typed, for free.
- **A version bump produces a diff.** Regenerating against the new spec and
  reading the diff is the authoritative list of what changed, replacing "read
  the release notes and hope".

The CLI's behaviour must not change. This is a refactor: every existing test and
smoke assertion passes unchanged, or the migration is wrong.

## 2. Verified findings

Measured on 2026-08-11 against the running v1.5.5 stack, with Kiota 1.34.1.

| question | finding |
|---|---|
| Native AOT | publishes clean, **zero IL/trim warnings**, with `TrimmerSingleWarn=false` |
| binary cost | the full CLI's AOT `linux-x64` binary grows **9.94 MB → 12.76 MB (+2.8 MB, +28%)**, and that ships on all six published RIDs. Startup is unaffected (12 ms `--help` on both). **The trimmer does remove unused generated code** — a bare probe with nothing called trims the 449-file client to 3.72 MB — but the growth is real: it's the Kiota runtime plus the request/response paths the CLI actually reaches. **Accepted — binary size is not a constraint for this tool at this order of magnitude.** Kiota registers Text/Form/Multipart serializers for a CLI that only speaks JSON, so `--structured-mime-types "application/json"` would trim some of it; not worth doing |
| build cost | 6.3 s to build 449 files / 54,602 lines; 14.2 s to AOT publish |
| `dotnet format` | `--verify-no-changes` exits 0 over the generated tree — `// <auto-generated/>` is respected, so CI does not fight it |
| query parameters | all 12 on `GET /api/systems` generated typed, including `parent_id` and `include_children` |
| request models | all 86 component schemas generated, including `GameSystemUpdate`, `GameSystemBulkItem`, `GameSystemBulkUpdate`, `BulkAddTags`. 84 are request bodies; 2 (`HTTPValidationError`, `ValidationError`) are response-only, generated because the 422 on 203 of the 207 operations references them |
| responses | 207 operations carry 410 responses total: 192 success responses (177×200, 15×201) type as `{}`, 15 are 204 (no body), and 203 are typed `HTTPValidationError` — the 422 that all but four operations declare. **No success response carries a schema**, so generated methods return `UntypedNode?` on the path we use and response DTOs stay hand-written |
| URL encoding | correct — `Dungeons & Dragons` encodes to `Dungeons%20%26%20Dragons`, the case the smoke test guards |
| empty query values | changed behaviour: `--genre ""` now sends `?genre=` instead of omitting the parameter (`QueryBuilder` omitted empty strings; the generated builders don't). Verified inert on v1.5.5 — both `systems` endpoints filter on Python truthiness, so an empty value behaves the same as no value. Would stop being inert against a future non-`Optional` parameter, where an empty value is a 422 and omission falls back to a default (e.g. `?limit=`) |
| request-only construction | `ToGetRequestInformation()` / `ToPatchRequestInformation()` build a full request **without executing it** |
| native request | `IRequestAdapter.ConvertToNativeRequestAsync<HttpRequestMessage>()` yields a native request we send ourselves, so the response body survives on errors — `SendPrimitiveAsync<Stream>` throws `ApiException` and discards it |
| our `HttpClient` | `new HttpClientRequestAdapter(provider, httpClient: ours)` accepts it, so `DebugHttpHandler`, the User-Agent, the auth header and the infinite timeout carry over unchanged |
| `baseurl` | filled by the adapter at send time; only needed manually when inspecting `RequestInformation.URI` before sending |
| path escaping | `../about` becomes `..%2Fabout`, so the traversal guard in `ApiEndpointsTests` is preserved. `.` and `""` both yield `/api/systems/`, which the server answers with the SPA catch-all (200 HTML) — the same exit 2 our smoke test already asserts |
| end to end under AOT | verified: 16 systems returned, container fields correct, matching the fixture set exactly |

Two spec quirks the generator surfaces:

- **No `servers` entry.** Kiota warns, and `RequestInformation.PathParameters["baseurl"]`
  must be set explicitly before the URI resolves.
- **Each query parameter is a single property**, not duplicated — nullability
  is chosen by an `#if NETSTANDARD2_1_OR_GREATER` compile-time switch. Only the
  deprecated `*RequestConfiguration` subclasses carry `[Obsolete]`, and they
  are unused.
- FastAPI's qualified schema names leak (`Backend__routers__books___schemas__LinkEntry`)
  and `anyOf` unions produce `…Member1` types. Ugly, harmless, and confined to
  models we do not use yet.

## 3. Architecture

The generator owns everything the spec describes. We own the documented gap and
the behaviour that makes this a CLI rather than an SDK.

```
generated builder.ToXRequestInformation()      →  URL, path params, query params, body
adapter.ConvertToNativeRequestAsync<HttpRequestMessage>()  →  native request
our HttpClient.SendAsync()                     →  full response, body included
our EnsureSuccessAsync + Deserialize           →  exit codes, hints, source-gen DTOs
```

**Kiota builds the request; we send it.** `SendPrimitiveAsync<Stream>` was the
obvious route and is the wrong one: it throws `ApiException` on any non-2xx and
discards the response body, which our error messages include verbatim
(`400 => "Bad request. {body}"`). Converting to a native `HttpRequestMessage`
and sending it ourselves keeps `EnsureSuccessAsync`, `WarnIfTokenExpired`, the
per-request `CancellationTokenSource` and `Deserialize` **completely unchanged**
— verified returning `401 {"detail":"Invalid token"}` with the body intact.

The change to `GrimoireApiClient` is therefore surgical: its methods take a
`RequestInformation` instead of a `string endpoint`. Nothing else moves.

| concern | owner | why |
|---|---|---|
| paths, methods, path parameters | **generated** | in the spec |
| query parameters | **generated** | in the spec, and typed |
| request bodies | **generated** | 84 of the 86 component schemas are request bodies |
| response types | hand-written | 0 of 410 responses carry a success schema |
| exit-code mapping (1/2/3) | hand-written | a CLI concern the spec knows nothing about |
| `permissionHint` / `notFoundHint` | hand-written | our 401/403/404 messages |
| login-time version check | hand-written | our compatibility policy |
| debug HTTP logging | hand-written | plugs into Kiota's `HttpClient` as a delegating handler |

**Why not the fully generated call path.** Generated methods return
`UntypedNode?`. Feeding that into our source-generated DTOs would mean
re-serializing an untyped tree back to JSON and parsing it again, on every read,
forever. `SendPrimitiveAsync<Stream>` hands us the response body directly, so
typed responses cost nothing extra.

### 3.1 What is deleted

- `src/GrimoireCli/Api/ApiEndpoints.cs` — path constants, superseded by builders.
- `src/GrimoireCli/Api/QueryBuilder.cs` — query-string assembly, superseded by
  generated query-parameter classes.

Their tests go with them; the behaviour they guarded is now the generator's, and
is covered by the smoke test's URL-encoding assertions.

### 3.2 What is generated, and where

**Everything — all 207 operations — committed to `src/GrimoireCli/Generated/`.**
Verified above as costing build time, repo size, and a measured +2.8 MB on the
published binary, without disturbing `dotnet format`.

Committed rather than generated at build time, for two reasons: building must
not require a running Grimoire, which would break CI and any fresh clone; and
the diff on regeneration *is* the version-bump safety mechanism, which only
exists if the previous output is in git.

`tools/generate-api-client.sh` wraps the invocation so regeneration is one
command with no arguments to misremember — the `/api/systems**` glob silently
dropped the bare `/api/systems` path during evaluation, and a script is how that
class of mistake stops recurring.

The spec comes from the running stack, never a file on disk (`CLAUDE.md`).

`.gitattributes` marks the tree `linguist-generated=true` so reviews collapse it.

## 4. Migration sequence

Behaviour-neutral throughout. Each step ends with the full gate set green.

1. **Generate and commit** the client, the script, and `.gitattributes`. Nothing
   consumes it yet, so the only risk is build and format, both measured.
2. **Migrate `systems list` and `systems get`** — the commands with real query
   parameters, and the ones whose smoke assertions are richest. This is where
   the architecture proves itself.
3. **Migrate `login`** and the `GET /api/about` version check.
4. **Delete `ApiEndpoints.cs` and `QueryBuilder.cs`** and their tests, once
   nothing references them.

The deferred systems write commands
([design](2026-08-10-systems-write-commands-design.md)) resume after this, and
its §3.2 is revisited: request DTOs now come from the generator, so the question
becomes whether `[JsonUnmappedMemberHandling(Disallow)]` behaviour is achievable
on generated types or must be wrapped.

## 5. Verification

The migration's correctness test is that **nothing observable changes**:

- All 115 unit tests pass unmodified, except those for deleted types.
- All 26 smoke assertions pass unmodified — including the ampersand round-trip,
  the `--sort bogus` parse-time rejection, and every count.
- `self-test` passes on the published AOT binary, which is where a missing
  `[JsonSerializable]` or a trimmed-away Kiota type would surface.
- `dotnet format --verify-no-changes` stays clean over the generated tree.

Plus the four pre-PR gates, and the AOT smoke run.

A regeneration check is worth having but is **not** a CI gate: it needs a running
Grimoire, and CI already spins one up only for the smoke job. Regenerating and
diffing is a documented step of the version-bump procedure
([grimoire-compatibility.md](../grimoire-compatibility.md)), not a test.

## 6. Out of scope

- Books, systems write commands, and `me` — all deferred behind this.
- Replacing `HttpClient` configuration wholesale. Kiota accepts a supplied
  `HttpClient`, so the User-Agent, timeout and `DebugHttpHandler` carry over
  as they are.
- Generating response types. There is nothing to generate from.
