# Target Grimoire 1.9.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Target Grimoire 1.9.0 as specified in `docs/specs/2026-10-16-grimoire-1.9.0-design.md`. That means re-pin, regenerate, raise the supported range to 1.9.0 – 1.9.0, and bring help and notes in line with 1.9.0 behaviour. No new commands.

**Architecture:** This follows `docs/grimoire-compatibility.md#handling-a-grimoire-release`.

## Global Constraints

- Branch `chore/grimoire-1.9.0`. `docker/docker-compose.yml` already pins `hunterreadca/grimoire:1.9.0`, uncommitted, and the local stack is running 1.9.0 at `http://host.docker.internal:9481`.
- Use Conventional Commits with **no `Co-Authored-By:` and no "Generated with" lines**.
- The bump commit is a plain `feat:`, not `!` or `BREAKING CHANGE:`. Its body states why the floor rises.
- Never hand-edit `src/GrimoireCli/Generated/`. Regenerate only with `bash tools/generate-api-client.sh`, and never run `kiota update`.
- Run `dotnet format GrimoireCli.sln` after C# edits.
- Do not add commands or flags. Do not change command behaviour without raising it first.
